# Protocol sufficiency analysis

Reads a methods section and reports, per checklist field, whether a **usable**
value is present. The hard case is not extraction — it is a field that is
present and supplies nothing (`"spun at high speed"`), or absent entirely and
therefore leaves no text to extract.

Start with **[`WRITEUP.md`](WRITEUP.md)** for the design reasoning and failure
analysis, and **[`defects_found.md`](defects_found.md)** for the 15 defects found
in the contract, field pack, lexicon and scorer.

---

## Deliverables

| # | Deliverable | Where |
|---|---|---|
| 1 | Code, in the given layout | this repository |
| 2 | `predictions/`, one JSON per paper, agreeing with `Report` | [`predictions/`](predictions/) — 9 files |
| 3 | Score table from `06_score.py`, with the `model=None` ablation | [`scores.txt`](scores.txt) — 4 panels, generated by `make_scores.py` |
| 4 | `WRITEUP.md`, 2–3 pages | [`WRITEUP.md`](WRITEUP.md) |

Deliverable 4's four required items map to `WRITEUP.md` §3 (failures, with the
cause attributed to our extractor / the field specification / your gold label),
§5 (hardest fields), §8 (three-week plan), §7 + `defects_found.md` (defects).

## Setup

```bash
python -m venv .venv
.venv/Scripts/activate          # Windows
source .venv/bin/activate       # POSIX
pip install -r requirements.txt
```

`-X utf8` is required on Windows for anything that reads `predictions/` —
`score.py` calls `Path.read_text()` with no encoding and dies on the `μ`, `–`
and `°` characters our findings quote. See `defects_found.md` D0.

## Inputs — read this before running

**The pipeline consumes plain text, not PDFs.** `analyze()` takes a `raw_text`
string and never opens a PDF; that is deliberate (see "The one function that
matters" below). So PDF extraction is a **separate step you run first**, and its
output is what the pipeline reads.

```bash
python extract_pdf_text.py          # papers_source/*.pdf  ->  papers/*.txt
```

Drop PDFs in `papers_source/`, run that once, and `papers/*.txt` appears. Only
then does `build_all.py` have anything to work on.

**Three input directories are deliberately not in this repository** — they are
your data, and re-uploading it would be noise:

| Directory | What to put there | Needed for |
|---|---|---|
| `papers/` | the methods text (or run `extract_pdf_text.py`) | everything |
| `gold/` | the supplied gold labels | the primary score panel |
| `R3 Dev Set/` | the R3 annotations | the secondary panel (optional) |

If `papers/` is empty the build still exits cleanly with **zero findings**, which
looks like a broken system rather than a missing input — so check it first.

## Run it

**One command builds and checks everything.** No API key needed, no spend.

```bash
python -X utf8 build_all.py
```

Exit code 0 means the pipeline ran and every generated deliverable is present.
It runs seven stages in dependency order — predictions, gold resolution for both
reference sets, `scores.txt`, the acceptance checks, the robustness suite — then
prints a deliverables checklist and any `TODO` still left in `WRITEUP.md`.

Add `--with-model` to regenerate the model run as well (replays from `cache/`
when present, otherwise needs `ANTHROPIC_API_KEY` and costs about $0.23):

```bash
python -X utf8 build_all.py --with-model
```

`scores.txt` is **derived** from `predictions/` and `predictions_model/`, which
persist independently — so the run order does not matter and a later run never
drops an earlier panel. Whichever prediction directories exist get scored.

<summary>The individual stages, if you want to run them separately</summary>

```bash
python run_all_predictions.py                    # deliverable 2, model=None
python run_all_predictions.py --model claude-opus-5   # optional, -> predictions_model/
python resolve_gold_anchors.py                   # gold anchors -> spans
python resolve_gold_anchors.py --gold "R3 Dev Set" --out gold_r3_resolved
python -X utf8 make_scores.py                    # deliverable 3
python -X utf8 verify.py                         # 19 acceptance checks
python -X utf8 stress_test.py                    # robustness
python -X utf8 anthropic_client.py               # one paper, shows the model's choices
```

## The one function that matters

`03_contract.py` says the harness calls exactly one function. That is
[`analyze.py`](analyze.py):

```python
from analyze import analyze
report = analyze(raw_text, doc_id, pack, model=None)
```

It is pure: no disk writes, no network except through the injected client, and
identical output on repeat calls. `run_all_predictions.py` is only a driver — it
does the two things `analyze()` is forbidden to do, namely read the field pack
off disk and write the JSON out.

## Structure

### The pipeline — the six steps of `02_BUILD_SPEC`

| File | Step | What it does |
|---|---|---|
| `analyze.py` | **all** | The entry point. Loops fields, not text. |
| `classify_study.py` | 1 | Which of the 9 `StudyFeature`s hold, with an evidence span each. Scanned over Methods only. |
| `sections.py` | — | Document tree (`Document → Methods → Subsections`), running-header and page-furniture guards, category matching. |
| `extract.py` | 3, 5 | Candidate retrieval; and the absence anchor — a walk up the tree for fields that are not stated. |
| `validate.py` | 4 | Every verdict. Unit and dimension parsing, enum surface forms, range detection. No model reaches this file. |
| `vagueness.py` | 4 | Typed, clause-scoped triggers (NegEx/ConText). Each trigger declares which slots it can fill. |
| `relevance.py` | 4 | Per-field evidence markers — what counts as actually stating this field. |
| `node_select.py` | 3, 5 | **The only module that may consult a model.** Returns an index into a list the code built. |
| `contract.py` | — | Frozen types. Supplied, unmodified. |

### Model plumbing — all optional

| File | What it does |
|---|---|
| `anthropic_client.py` | Sends one prompt, returns one string. Token budget, spend warning, cost report. |
| `model_cache.py` | Prompt-hash cache with hit/miss accounting. Makes repeat runs free and pins determinism. |
| `mock_client.py` | Echo / scripted / word-overlap stand-ins, so the model path is testable with no key. |

### Tooling

| File | What it does |
|---|---|
| `build_all.py` | **Start here.** Runs every stage in order, generates all deliverables, checks them, exits non-zero on failure. |
| `run_all_predictions.py` | Runs `analyze()` over every paper, writes `predictions/`. |
| `resolve_gold_anchors.py` | Turns gold `anchor_text` into the `span` `score.py` needs. The script the bundle references but does not contain — `defects_found.md` A2. |
| `make_scores.py` | Generates `scores.txt` by invoking the real `score.py`. Nothing in that file is hand-typed. |
| `verify.py` | 19 acceptance checks. Exits non-zero on failure. |
| `stress_test.py` | Perturbation and adversarial-input suite. |
| `score.py` | Supplied scorer, unmodified. |
| `extract_pdf_text.py` | One-time utility that produced `papers/*.txt`. **Not in the pipeline** — `analyze()` takes text and never touches a PDF. |

### Data

| Path | What it is |
|---|---|
| `papers/` | Methods sections, plain text. Supplied. |
| `fields/oncobiology_v0.yaml` | The 27-field pack. Supplied, unmodified. |
| `vagueness.yaml` | Seed lexicon. Supplied, unmodified. |
| `gold/` → `gold_resolved/` | Supplied gold, anchors resolved to spans. |
| `R3 Dev Set/` → `gold_r3_resolved/` | Secondary reference, kept separate on purpose — different provenance. |
| `predictions/` | **Deliverable 2.** `model=None`. |
| `predictions_model/` | Optional model run. Not a deliverable. |

Diagnostic scripts (`show_findings.py`, `show_matches.py`, `diagnose_scoping.py`,
`run_field_loop.py`, `run_all_papers.py`) print intermediate stages. They are the
harness the failure analysis was built with, not part of the pipeline.

## Two things to know before reading the numbers

**`model=None` is the shipped configuration.** Every file in `predictions/` comes
from the deterministic layer alone. `01_README.md` says that number "is not a
failure condition", and it is what a grader reproduces with no credentials. The
model contributes to exactly one decision — which subsection an absent field
anchors to — and after a confidence floor it is consulted 19 times across nine
papers.

**The two reference sets disagree in shape, and that is the main finding.** The
supplied gold is 13 `GAP_ABSENT` of 18 labels; the R3 set is 29 `GAP_VAGUE` of
49. We score 0.286 F1 on the first slice and 0.000 on the second. `WRITEUP.md`
§6 treats that as evidence we are fitted to the label distribution rather than to
surface forms — the perturbation suite passes because it re-scores the same
paper.
